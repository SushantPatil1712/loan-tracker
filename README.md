# Loan EMI & Repayment Tracker API

A REST API built with **Python and FastAPI** that creates loans, generates a month-by-month EMI repayment schedule, records payments and flags overdue installments. Data is stored in a relational SQL database (SQLite) and the code is covered by automated tests.

## Features

- Create borrowers and loans; the EMI and the full amortization schedule are generated automatically
- Record installment payments; a loan closes automatically when its last installment is paid
- List overdue installments with borrower details and days overdue
- Input validation with clear HTTP status codes (201, 400, 404, 409, 422)
- Interactive API docs at `/docs` (generated by FastAPI)

## Tech stack

Python 3.9+ · FastAPI · Pydantic · SQLite (plain SQL) · pytest


## API overview

| Method | Endpoint | Description |
|---|---|---|
| POST | `/borrowers` | Create a borrower (duplicate email returns 409) |
| POST | `/loans` | Create a loan and generate its schedule |
| GET | `/loans/{id}` | Get a loan |
| GET | `/loans/{id}/schedule` | Get all installments for a loan |
| POST | `/installments/{id}/pay` | Record a payment (paying twice returns 409) |
| GET | `/installments/overdue` | List overdue installments (`?as_of=YYYY-MM-DD` optional) |

## Design decisions

- **Money is stored as integer paise, not floats.** Floating-point arithmetic gives errors such as `0.1 + 0.2 = 0.30000000000000004`, which is unacceptable for financial data.
- **Reducing-balance EMI.** Interest each month is calculated on the outstanding balance. Because the EMI is rounded to whole paise, the final installment is adjusted so the balance ends at exactly zero.
- **Transactions.** A loan and all of its installments are saved together or not at all. A payment, the installment status change and the loan closing also commit as one unit.
- **Safe against double payment.** `UPDATE ... WHERE status = 'PENDING'` makes the check and the change one atomic step, so two simultaneous requests cannot both succeed.
- **Database-level constraints.** `CHECK`, `UNIQUE` and foreign-key constraints in `schema.sql` reject bad data even if the application code has a bug.
- **Indexed overdue query.** A composite index on `(status, due_date)` supports the overdue lookup, and a test checks with `EXPLAIN QUERY PLAN` that it is actually used.
- **Parameterized queries.** All SQL uses `?` placeholders to prevent SQL injection.

## Project structure

```
main.py          API endpoints
emi.py           EMI formula and amortization schedule
dates.py         Month arithmetic with end-of-month handling
db.py            Database connection and setup
schema.sql       Table definitions, constraints, indexes
conftest.py      Shared test fixture (fresh database per test)
test_*.py        Unit and API tests
```

## Limitations and next steps

- Payments must cover a full installment (no partial payments or prepayment yet)
- No authentication
- SQLite is used for simplicity; PostgreSQL would be the choice for production
- Possible additions: pagination on list endpoints, Docker, a simple front end
